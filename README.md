### 🔴 CyberSim — Cyber Attack Simulator
> **Android application** that simulates real-world cyberattack patterns for security education and awareness training

![Android](https://img.shields.io/badge/Android-3DDC84?style=flat-square&logo=android&logoColor=white)
![Java](https://img.shields.io/badge/Java-ED8B00?style=flat-square&logo=openjdk&logoColor=white)
![Security](https://img.shields.io/badge/Cybersecurity-E24B4A?style=flat-square&logo=hackaday&logoColor=white)

**What it does:**
CyberSim is an offline educational tool that lets users explore how real cyberattacks are structured and how they propagate — without touching any real network. It's designed for CS students, security beginners, and awareness training sessions.

- 🎯 Simulates attack vectors: phishing flows, brute-force patterns, packet sniffing, MITM, and social engineering scenarios
- 🗺️ Visual attack-path renderer shows step-by-step how an exploit moves through a simulated network graph
- 🛡️ Defense mode: users identify vulnerabilities in the simulated environment and apply patches — teaches both sides of security
- 📊 Post-simulation report card scores the user's attack efficiency or defense success
- 🔒 Fully sandboxed, fully offline — no real network activity, no real data at risk
- 📱 Clean Android UI with animated threat visualizations and intuitive navigation

**Why I built it:** Security concepts are hard to learn passively. Simulation creates real understanding. CyberSim turns abstract attack theory into something you can interact with and see.

`Android SDK` · `Java` · `XML` · `SQLite` · `Canvas API`

**Why I built it:** Most health apps track calories. BioTech tracks nutrition — because what you eat matters more than how much.

### 🖥️ Assembly Language Projects
> **Low-level systems programs** written in x86 Assembly — direct hardware interaction, no abstractions

![Assembly](https://img.shields.io/badge/Assembly-6E4C13?style=flat-square&logo=assemblyscript&logoColor=white)

**What I've built:**
Understanding a machine at the bare-metal level is one of the rarest skills a developer can have. These projects exist because I believe every programmer should understand what their high-level code compiles down to.

- 🔢 Arithmetic processors operating on registers directly — no stdlib, no runtime
- 🖥️ Console I/O routines using BIOS interrupts
- 🔄 Sorting algorithms in Assembly: understanding why O(n²) matters when you see the instruction count
- 🧠 Memory-mapped operations and stack discipline from scratch

**Why I built these:** Most developers never touch Assembly. I did it deliberately — because understanding the instruction set makes you think differently about every line of code you write above it.

`x86 Assembly` · `NASM/MASM` · `Registers` · `BIOS Interrupts` · `Memory Management`
